# Deck Build Run Manifest

Use this reference when creating, resuming, or finalizing a page-worker deck build run.

## Directory Shape

Recommended run directory:

```text
exp/ppt_deck_build/<run_id>/
  deck_build_manifest.json
  work_order.json
  page_jobs.json
  page_jobs_status.json
  repair_backlog.md
  assembly_log.md
  pages/
    slide_001/
      page_request.json
      page_result.json
      page_validation.json
      slide_fragment.pptx
      slide_instructions.json
      preview.png
```

## `work_order.json`

The work order is the scheduler input. It should be produced from confirmed upstream artifacts and then human-confirmed before page worker dispatch.

Required fields:

```json
{
  "schema": "ppt_deck_build_work_order.v1",
  "stage_status": "confirmed",
  "run_id": "20260601-example",
  "deck": {
    "title": "Deck title",
    "output_name": "deck_v0",
    "template_path": "path/to/template.pptx"
  },
  "sources": {
    "production_brief": "path",
    "fact_ledger": "path",
    "defense_narrative": "path",
    "storyboard": "path",
    "speaker_notes_rehearsal": "path",
    "defense_qa_backup": "path",
    "asset_layout_plan": "path",
    "content_fidelity_qa": "path"
  },
  "scheduler": {
    "requested_max_workers": 4,
    "fallback_policy": "stop_without_native_subagents"
  },
  "slides": []
}
```

Each `slides[]` item becomes one page request.

## `page_jobs.json`

Generated by `prepare_deck_build_run.py`.

```json
{
  "schema": "ppt_page_jobs.v1",
  "run_id": "20260601-example",
  "jobs": [
    {
      "slide_id": "S01",
      "slide_number": 1,
      "status": "queued",
      "request_path": "pages/slide_001/page_request.json",
      "output_dir": "pages/slide_001"
    }
  ]
}
```

## `page_jobs_status.json`

Mutable run status, updated as page worker results arrive.

Allowed job statuses:

- `queued`
- `running`
- `done`
- `needs_repair`
- `blocked`
- `failed`

The scheduler may resume a run by dispatching only `queued`, `blocked` after human repair, or `needs_repair` after a repair decision. It must not overwrite `done` slide outputs unless the user explicitly requests a rebuild.

## `deck_build_manifest.json`

Run-level evidence file. Required fields:

```json
{
  "schema": "ppt_deck_build_manifest.v1",
  "stage": "deck_build",
  "stage_status": "draft",
  "run_id": "20260601-example",
  "work_order_path": "exp/ppt_deck_build/20260601-example/work_order.json",
  "page_jobs_path": "exp/ppt_deck_build/20260601-example/page_jobs.json",
  "status_path": "exp/ppt_deck_build/20260601-example/page_jobs_status.json",
  "repair_backlog_path": "exp/ppt_deck_build/20260601-example/repair_backlog.md",
  "generated_pptx_path": null,
  "page_counts": {
    "total": 0,
    "done": 0,
    "needs_repair": 0,
    "blocked": 0,
    "failed": 0
  },
  "allowed_next_stage": "ppt-render-qa-loop"
}
```

Use `stage_status: draft` until the user confirms the generated editable deck draft is ready for render QA.

## Repair Backlog

`repair_backlog.md` is append-friendly and human-readable.

Each item should include:

- slide ID and slide number
- status
- severity: `low`, `medium`, `high`, or `blocking`
- defect summary
- likely owner: `page_worker`, `scheduler`, `asset_layout_plan`, `storyboard`, `source_material`, or `human`
- recommended next action
